# Security policy

The canonical, complete security policy for Big Plan lives on the documentation site:

**https://big-plan.ai/reference/security/**

That page owns the reporting process, the response timelines, the supported-version policy, the distribution and supply-chain notes, and the security model of the local review runtime.
This file exists so GitHub can offer its **Report a vulnerability** affordance, and it deliberately does not restate that content.

## Reporting a vulnerability

Report privately through GitHub — not in a public issue, pull request, or discussion:

[**Open a private security advisory**](https://github.com/josh-padnick/big-plan/security/advisories/new)

Include what an attacker can do, the version you tested, and the smallest reproduction you have.
You can expect an acknowledgement within 3 business days.

Big Plan is pre-1.0: only the latest published version on npm receives security fixes.

See [the security page](https://big-plan.ai/reference/security/) for scope, what is explicitly out of scope, and the full disclosure process.

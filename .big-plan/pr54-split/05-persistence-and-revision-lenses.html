Make review recovery complete

Harden every mutable review transition and preserve typed meaning across revisions for all registered components.

Quick summary

Why
Review trust depends on surviving crashes, stale tabs, rebases, and component-rich revisions without inventing state.
What
Add atomic persistence, recovery and reconciliation, explicit browser workflow state, and component-owned revision lenses.
How
  • Commit mutable files atomically and recover interrupted submissions.
  • Reject stale writes and reconcile stable plan identity after rebases.
  • Let every component define its typed revision snapshot and comparison.

Part 1Context

1.1 / Inherited product

Inherited product

  • Slices one through three establish the review server, live agent loop, and complete commenting workflow.
  • Slice four makes visual ownership and causal revision behavior mechanically explicit, and repairs the capture harness so its expanded sent-thread state is bootstrapped through the production ownership boundary.
  • This slice addresses the failure modes that appear only across interruptions, concurrent tabs, rebases, and typed component changes.

1.2 / Success looks like

Success looks like

  • An interrupted save cannot expose a half-written reviewer snapshot.
  • Restarting adopts the last committed review state and reconciles any browser recovery mirror.
  • A stale tab cannot overwrite newer reviewer work; it reloads and merges only the drafts it still owns.
  • Every registered component compares revisions through a lens that preserves its authored type and semantics.
Part 2The slice

2.1 / The hardening pass

The hardening pass

Atomic repository. Mutable state files use same-directory temporary writes, flush, atomic replacement, and directory flush; immutable requests, responses, revisions, packages, and activity events remain append-only facts.

Submission recovery. Feedback commit records make interrupted submission replayable, while optimistic reviewer revisions reject stale writes and preserve concurrent drafts.

Identity reconciliation. A main-branch rebase can change plan identity without orphaning its review; the runtime recognizes and reconciles the durable lineage.

Explicit browser workflows. Reducer-like actions own composition, submission, navigation, connection, cancellation, and recovery transitions instead of scattering state mutations through event handlers.

Typed revision lenses. The registration contract requires all eighteen built-in components to serialize and compare their own typed data, while renderer-only instance keys remain internal.

Part 3Shipping & your review

3.1 / Review boundaries

Review boundaries

  • This slice contains every source change from origin/fm/bp-commenting-round3.
  • Its final tree differs from that source head only by slice four's capture-harness bridge. Removing that one bridge patch produces the exact PR 54 tree.
  • It adds no compatibility shim: Big Plan remains pre-release and updates every call site to the clean contract.
  • Historical preview reports and evidence land with the slice that produced them; they document the tested UX rather than defining runtime behavior.
  • Earlier slices contain narrow test, selector, generated-asset, and visual-evidence bridges so each intermediate branch remains green; all net final-tree bridges except the authorized capture fix reconcile back to PR 54.

3.2 / Acceptance criteria

Acceptance criteria

  • bun run build, bun run lint, bun run test, and bun run test:e2e pass on this branch.
  • Atomic replacement and interrupted-feedback tests prove recovery at every mutation boundary.
  • Concurrent stale-tab tests preserve newer state and merge only valid owned drafts.
  • Browser workflow tests cover composition, submission, cancellation, navigation, reconnect, and recovery actions.
  • The revision-contract check and browser journey cover all eighteen registered component lenses.
  • The direct diff from origin/fm/bp-commenting-round3 changes only scripts/style-snapshots/capture.mjs.
  • The patch-id of that direct diff exactly matches the authorized capture bridge commit, and reverse-applying it yields PR 54's tree object.

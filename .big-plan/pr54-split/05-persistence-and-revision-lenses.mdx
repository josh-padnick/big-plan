## Success looks like

- An interrupted save cannot expose a half-written reviewer snapshot.
- Restarting adopts the last committed review state and reconciles any browser recovery mirror.
- A stale tab cannot overwrite newer reviewer work; it reloads and merges only the drafts it still owns.
- Every registered component compares revisions through a lens that preserves its authored type and semantics.

<Part title="The slice" />

## The hardening pass

**Atomic repository.** Mutable state files use same-directory temporary writes, flush, atomic replacement, and directory flush; immutable requests, responses, revisions, packages, and activity events remain append-only facts.

**Submission recovery.** Feedback commit records make interrupted submission replayable, while optimistic reviewer revisions reject stale writes and preserve concurrent drafts.

**Identity reconciliation.** A main-branch rebase can change plan identity without orphaning its review; the runtime recognizes and reconciles the durable lineage.

**Explicit browser workflows.** Reducer-like actions own composition, submission, navigation, connection, cancellation, and recovery transitions instead of scattering state mutations through event handlers.

**Typed revision lenses.** The registration contract requires all eighteen built-in components to serialize and compare their own typed data, while renderer-only instance keys remain internal.

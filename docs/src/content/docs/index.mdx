<p class="eyebrow">The problem</p>

## The most important document in the workflow is the least readable one

An agent's plan usually arrives as thousands of words of Markdown, scrolled past in a terminal or
skimmed in a raw diff. When reading the plan is painful, review quietly collapses into
rubber-stamping — and the decisions that matter most go unexamined.

The big decisions happen in the plan, while they are still cheap to change. Once execution
starts, changing course means unwinding work. While the plan is on the table, changing everything
costs one comment.

<p class="eyebrow">Set up</p>

## One prompt, and your agent does the rest

Paste this into your coding agent. It needs Node.js 22 or newer and installs nothing globally.

```text
Set up Big Plan for me: read https://bigplan.dev/setup.md and follow it.
```

The linked setup guide is server-controlled and stays current as Big Plan changes, so the prompt
never has to. Prefer to do it yourself? `npx -y big-plan@latest guidance` prints the plan-writing
principles and unlocks the rest of the workflow for that directory.

</section>

<p class="eyebrow">First-class rendering</p>

## A plan is not one kind of information, so it should not render as one

Most of a plan is prose, and prose renders as prose. But a plan also carries decisions, code
changes, schemas, file moves, API contracts, and screens — and each of those reads far better as
the thing it is than as another paragraph describing it.

So Big Plan gives twenty kinds of plan information their own **first-class rendering**. The agent
picks the right one and fills in the content; it never designs a layout, which is why the tenth
plan you review reads exactly like the first.

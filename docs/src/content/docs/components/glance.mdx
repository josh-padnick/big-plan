`Glance` shows the whole argument before the reader commits to any of it: one row per section, each row a link carrying the section title and its one-line gist.
Big Plan completes the overview at render time with slide numbers, section links, and group headers derived from the plan's [Part](/components/part/) dividers, so the author writes only the items.

## When to use it

Place one `Glance` directly after the `QuickSummary`, before the first `Part` or section.
Skip it only in a very short plan whose table of contents already tells the whole story.

## Authoring

```mdx
<Glance>
<Item section="Status quo" gist="Inline retries couple checkout latency to processor health" />
<Item section="Success looks like" gist="A restart never loses a scheduled retry" />
<Item section="The retry queue" gist="A queue worker with explicit state and bounded backoff" />
</Glance>
```

## The contract

- At least one self-closing `Item`, each with required non-empty `section` and `gist` attributes; loose body content is rejected.
- `section` must repeat the document's h2 titles exactly, in order, one to one, enforced by the `glance-matches-sections` linting rule.
- No attributes on `Glance` itself.

Each violation fails `validate` and `render` with a positional diagnostic.
Run `big-plan guidance Glance` for judgment-level usage guidance.

`SimpleDecisionSet` collects the small questions a plan poses to its reviewer - typically at the end - as one compact numbered list.
Each question offers two or more options, and each option pairs its title with a short explanation, enough to answer quickly without a tradeoff card.
A choice weighty enough to need a structured tradeoff comparison belongs in a standalone [ComplexDecision](/components/complex-decision/) instead.
The recommended answer carries a clear inline badge; selecting and recording answers arrives with the live review layer.

## When to use it

Use `SimpleDecisionSet` for the quick calls that remain after the plan's substance is settled: rollout toggles, naming, sequencing, defaults.
Phrase every question as a question, keep option explanations to a sentence or two, and mark the recommended answer so an agreeing reviewer can confirm at a glance.

### When not to use it

- A decision with real tradeoffs to weigh - use [ComplexDecision](/components/complex-decision/)
- A single yes/no confirmation the surrounding prose can carry
- Questions with no concrete options yet - leave them as prose until the options exist

## Use cases

- Close a plan with the open questions a reviewer must answer before implementation starts
- Collect scattered small calls into one place instead of burying them across sections
- Show recommended defaults so review can be a fast confirmation pass

## Usage

````mdx
<SimpleDecisionSet title="Open questions">

Answer these before implementation starts.

<SimpleDecision question="Should the first release ship behind a feature flag?">

The rollout risk is concentrated in the first week.

<Option title="Yes" recommended>

Keeps rollback one toggle away during the risky window.

</Option>

<Option title="No">

Avoids the flag-cleanup follow-up task.

</Option>

</SimpleDecision>

</SimpleDecisionSet>
````

## Authoring

### SimpleDecisionSet

An optional `title` labels the list, and the header always counts the questions.
Introductory markdown before the first `SimpleDecision` explains what the list covers.

### SimpleDecision

Nest one or more `SimpleDecision` elements directly inside the set.

| Attribute  | Type               | Required | Behavior                                    |
| ---------- | ------------------ | -------- | ------------------------------------------- |
| `question` | string (non-empty) | Yes      | Renders as the numbered question line.      |

Markdown before the first `Option` supplies optional context for the question.
Each question needs at least two options.

### Option

| Attribute     | Type               | Required | Behavior                                                     |
| ------------- | ------------------ | -------- | ------------------------------------------------------------ |
| `title`       | string (non-empty) | Yes      | Names the option; titles must be unique within the question. |
| `recommended` | bare boolean       | No       | Marks at most one option per question as Recommended.        |

Markdown in the option body is the short always-visible explanation; an option may omit it when the title alone is enough.

`SimpleDecision` must be a direct `SimpleDecisionSet` child, and `Option` must be a direct `SimpleDecision` child.
Their markdown bodies accept prose, lists, inline formatting, and plain fenced code, but reject headings, footnotes, and typed components with positional diagnostics.

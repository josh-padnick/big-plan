# Harbor across three form factors

Sketch the Harbor support inbox natively for desktop, tablet, and phone.

Each form factor is a parallel prototype so reviewers compare real device layouts rather than one layout with different captions.

## Desktop web SaaS

One consistent pane model: fixed global nav, then workspace panes (list, main, details).
Content hierarchy comes from type and layout; major panes use dividers rather than competing card outlines.

### Ticket - design rationale (priority 1)

- **Pattern:** Front / Zendesk **three-pane** - compact queue | conversation timeline | properties rail.
- **Structure:** Properties and Related sit in a **right rail**, not under the queue. Conversation is the widest column. Composer is pinned under the timeline.
- **State:** Current ticket is selected in the queue; titles match the inbox subject line.
- **Messages:** Timeline with customer / agent / internal kinds, not table rows.
- **Actions:** Segmented Reply vs Internal note; **Send reply** primary.

### Inbox - design rationale

- **Pattern:** Front / Intercom **list + inspector**.
- **Scanning:** Rows use stable columns (subject, status·assignee, age·id); selected row is tinted with an edge accent.
- **Views vs filters:** saved views (All / Mine / Unassigned) separate from filter chips (Waiting, SLA risk), with counts.
- **Inspector:** no generic "Selected" heading; slightly wider preview; **View ticket** (not external-arrow language).
- **Tools:** search and sort near the header.

### New ticket - design rationale

- **Pattern:** Linear / GitHub **create form + routing rail**.
- **Order:** Customer → Subject → Description.
- **Duplicates:** only after subject text exists; actions Open / Link / Dismiss.
- **Routing:** "Suggested from similar tickets" explanation.
- **Actions:** **Create ticket**, **Send a confirmation email** with destination address.

### Settings - design rationale

- **Pattern:** Linear / Stripe **settings nav + form**.
- **Dependencies:** Digest hour disabled while digest is off; Slack channel note when Slack alerts off; hints under the affected control.
- **Sections:** Notifications, Channels, Digest (named, not a lone divider).
- **Save model:** explicit Save/Discard with an unsaved-changes bar (not only a tiny badge).
- **Measure:** form column capped for readability.

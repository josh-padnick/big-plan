# Harbor across three form factors

Sketch the Harbor support inbox natively for desktop, tablet, and phone.

Each form factor is a parallel prototype so reviewers compare real device layouts rather than one layout with different captions.

## Desktop web SaaS

Persistent left nav + content workspace.
Every desktop screen names a real product pattern; on-screen copy is product UI only (no keyboard cheatsheets or layout notes inside the artboard).

### Inbox - design rationale

- **Pattern:** Front / Intercom **list + inspector** (dense queue, selected row previewed in a side panel).
- **Width for context:** queue claims most of the canvas; inspector holds the selected ticket and one SLA metric - not a second dashboard of cards.
- **Hierarchy:** one primary action (`New ticket`); views are quiet tertiary filters; open the selected ticket from the inspector, not a second CTA under the list.
- **CRAP:** repeated list-row structure; filters and header aligned; preview content is proximity-grouped under one panel.
- **Shell:** global nav stable (Inbox active); views stay in content, not as global destinations.

Self-critique fixed before present: removed keyboard meta from the UI; removed under-list "Open selected"; collapsed dual Preview/Attention panels into one inspector.

### Ticket - design rationale

- **Pattern:** Front / Zendesk **three-pane workspace** (queue | conversation | properties).
- **Width for context:** queue stays so triage continues; conversation is the primary surface; properties are a narrow rail - not equal thirds.
- **Hierarchy:** `Resolve` is the page primary; `Send` is the thread primary; `Internal` is tertiary next to `Reply` mode.
- **CRAP:** same global shell as every other screen; related fields grouped under Properties; Related list sits under them.
- **Shell:** Inbox remains active; no separate "back" control - the queue is the navigation.

Self-critique fixed: stripped layout/keyboard meta; removed redundant "Back to full inbox"; stopped putting process notes in the composer.

### New ticket - design rationale

- **Pattern:** Linear / GitHub **create page** (main form + right context rail).
- **Width for context:** full-width subject/description in the main column; rail holds duplicate detection and routing only.
- **Hierarchy:** one primary `Create ticket`; Cancel is tertiary; rail has no competing primary.
- **CRAP:** form fields stack with shared left edge; routing controls grouped; duplicate list sits above them.
- **Shell:** same global nav; Inbox not active (create is a route off inbox).

Self-critique fixed: removed draft/sticky meta copy; shortened receipt hint to product language.

### Settings - design rationale

- **Pattern:** Linear / Stripe **settings two-column** (section nav + single field column).
- **Width for context:** sub-nav is a rail; fields fill one readable column - not two equal cards.
- **Hierarchy:** page title is the section name; `Save` is the only primary; Discard is tertiary for dirty state.
- **CRAP:** nav items repeat the same row treatment; switches and selects align as one vertical rhythm.
- **Shell:** Settings active in global nav.

Self-critique fixed: no instructional helpers; no fake "search settings" without a search field; denser field stack without decorative panels.

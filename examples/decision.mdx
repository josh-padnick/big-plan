# Skill Distribution Decision

Choose the delivery channel before implementing the installer.

<Decision question="How does the skill reach the user's agent?">

The repository copy remains canonical either way.

<Option title="Embed it in the CLI" recommended summary="A command prints the version-matched skill.">

<Consideration label="Version fidelity" verdict="Exact" tone="good">

The installed package contains the matching skill text.

</Consideration>

<Consideration label="Offline setup" verdict="Yes" tone="good">

Installation never needs the network.

</Consideration>

</Option>

<Option title="Download it from the docs site" summary="Setup fetches the published skill.">

<Consideration label="Version fidelity" verdict="May drift" tone="bad">

The site can move ahead of an older CLI.

</Consideration>

<Consideration label="Offline setup" verdict="No" tone="bad">

Setup must reach the documentation host.

</Consideration>

</Option>

</Decision>

<Decision question="Where does the installer put the skill?" state="decided">

Settled before this review began; it is recorded here so the rest of the plan can rely on it.

<Option title="The agent's own skills directory" chosen summary="The agent finds it without configuration.">

<Consideration label="Discovery" verdict="Automatic" tone="good">

The agent already reads that directory at startup.

</Consideration>

<Consideration label="Isolation" verdict="Per user" tone="good">

Nothing outside the user's home is written.

</Consideration>

</Option>

<Option title="A shared system directory" summary="One copy serves every user on the host.">

<Consideration label="Discovery" verdict="Needs a path" tone="bad">

Each agent must be told where to look.

</Consideration>

<Consideration label="Isolation" verdict="Host-wide" tone="bad">

Installation needs elevated permissions.

</Consideration>

</Option>

</Decision>

# Slide types turn labels into writing help

This preview shows how catalog names, plan-specific titles, and type guidance work together in one review document.

<QuickSummary>

<Why>

- Agents need concrete writing help for slide roles that recur across plans.

</Why>

<What>

- Connect typed slides to role-specific guidance while keeping each heading free to state the plan's message.

</What>

<How>

- Derive navigation names from a closed catalog.
- Keep plain-language titles in authored h2 headings.
- Apply each type's guidance only when its matching rule fits.

</How>

</QuickSummary>

<Part title="Context" />

<Slide type="status-quo" />

## Agents rebuild common slide roles from scratch

Two plans can contain the same conceptual slide under unrelated headings.
The renderer can present both, but general guidance cannot reliably teach the different craft of a status slide, a human journey, and a verification contract.

The existing heading model still works well: an h2 gives every slide a readable headline, stable anchor, and collapsible section.
The missing piece is a stable hook for advice that belongs to one recurring role.

<Callout type="note" title="Status quo guidance applied">

- Start with observable authoring behavior and its consequence.
- Preserve what already works in the heading model.
- Keep the symptom of repeated invention distinct from the missing type hook.

</Callout>

## Success looks like

- An agent reads the complete catalog once, then applies the matching guidance throughout the authoring pass.
- A typed slide carries a stable structural name and a plan-specific title.
- A slide that does not fit the catalog remains naturally untyped.

<Part title="The authoring experience" />

<Slide type="desired-experience" />

## Agents match a slide before they draft it

As an agent, I state what the next slide must help the reviewer understand or decide.
I compare that intent with the catalog's matching boundaries.
When a type fits, I follow its writing advice and component pairings; when none fits, I use the general guidance without inventing a local label.

<Callout type="note" title="Desired experience guidance applied">

- Describe what the author can see, decide, and do.
- Keep the experience separate from registry and renderer mechanics.
- Use first-person language where it makes the change tangible.

</Callout>

<Part title="Verification" />

<Slide type="acceptance-criteria" />

## Generated plans expose each type's writing contract

- One `big-plan guidance Slide` call returns all five type records, including matching boundaries, writing advice, component pairings, and cardinality.
- Most typed slides render the catalog name in their kicker and navigation; user journeys render their marker name there, and all preserve the authored h2 as the title.
- Two `user-journey` markers render with distinct journey names, ultra-concise overview forms, and full h2 claims under a “User journeys” container.
- “Success looks like” remains an untyped, canonical section and produces no lint finding.
- A title with strained marketing language remains a guidance concern rather than a blocking language diagnostic.
- The rendered document remains readable and interactive in light and dark color schemes.

<Callout type="note" title="Acceptance criteria guidance applied">

Every item names an observable command result, rendered behavior, or lint boundary.
The list verifies completion without prescribing implementation steps.

</Callout>

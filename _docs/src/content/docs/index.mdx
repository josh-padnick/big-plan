<p class="eyebrow">The problem</p>

## The most important document in the workflow is the least readable one.

An agent plan usually arrives as a wall of text. Or maybe if you are lucky, an HTML artifact,
but there is still no avoiding verbosity, awkward wording, and just plain too much text.

And yet the best big decisions happen in the plan, where they are still cheap to change.

</section>

<section class="band">

<p class="eyebrow">The solution</p>

## Reading agent plans should be enjoyable

<p class="band-lede">
  A plan is a designed document, not an accident of generation — so design it for the person
  reading it. Five things make a plan human-friendly.
</p>

<div class="value-grid">
  <div>
    <h3>Easy to navigate</h3>
    <p>A table of contents, organized by section, summary cards, and first-class rendering for decisions, diffs, schemas, mockups, and more.</p>
  </div>
  <div>
    <h3>Easy to read</h3>
    <p>Big Plan gives agents special guidance on how to write content that is enjoyable for humans to read.</p>
  </div>
  <div>
    <h3>Add comments</h3>
    <p>Comment on any part of the plan. Send it to your agent immediately, or in batch with other comments.</p>
  </div>
  <div>
    <h3>Make decisions</h3>
    <p>The plan can ask you questions. Answer them directly in the plan.</p>
  </div>
  <div>
    <h3>All local</h3>
    <p>Big Plan requires no account or hosted service so all your plans stay local.</p>
  </div>
</div>

</section>

<section class="band band-quiet">

<p class="eyebrow">Set up</p>

## One prompt, and your agent does the rest

Paste this into your coding agent. It needs Node.js 22 or newer and installs nothing globally.

```text
Set up Big Plan for me: read https://bigplan.dev/setup.md and follow it.
```

</section>

<p class="eyebrow">First-class rendering</p>

## A library of components for common information patterns

Plans can carry decisions, code changes, schemas, API contracts, mock-ups and more. Big Plan
renders common information patterns in a first-class way by shipping a growing library of
components. The agent picks the right component and fills in the content.

## One queue, one owner

*The worker owns retry timing; checkout only records the failed attempt.*

The API writes a job and returns immediately. A worker leases the oldest ready
job, applies exponential backoff, and records the terminal outcome.

| Field | Meaning |
| --- | --- |
| `attempt` | Number of completed delivery attempts |
| `readyAt` | Earliest time another worker may lease the job |
| `leaseOwner` | Worker currently responsible for the attempt |

<CodeSnippet file="src/retry/next-delay.ts" startLine="1" showLineNumbers>

```ts
export const nextDelay = (attempt: number): number =>
  Math.min(30_000, 500 * 2 ** attempt);
```

</CodeSnippet>

## Ready when the loop is honest

- Every failed payment has one durable state.
- A lease expiry makes the job available without duplicating a successful send.
- Exhausted jobs remain visible to an operator.
- Metrics distinguish queued, leased, retried, succeeded, and exhausted work.

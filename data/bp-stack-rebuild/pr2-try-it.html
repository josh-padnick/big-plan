Review an agent-authored revision

Use the same thin thread kernel while a real coding-agent session rewrites this plan and reports only outcomes Big Plan can verify.

Quick summary

Why
Reviewers need to know whether the plan actually changed.
What
Connect each feedback package to one local coding-agent conversation.
How
Snapshot source revisions, validate outcomes, and show exact-path orphaning.
Part 1Try the loop

1.1 / Send one bounded rewrite

Send one bounded rewrite

The worker owns retry timing; checkout only records the failed attempt.

Add a note to the sentence above asking the agent to remove it and clarify delivery ownership below. Send the note, run big-plan agent in another terminal, and launch the returned coding-agent command.

State What it proves
With agent A request exists, but no response does
Changed The source digest changed and named blocks are in the diff
Needs your answer The agent needs reviewer judgment
Outside this plan The request cannot be solved by editing this MDX

1.2 / Inspect revision truth

Inspect revision truth

The API writes a job and returns immediately. A worker leases the oldest ready job, applies exponential backoff, and records the terminal outcome.

After the coding agent responds, choose What changed before reloading. Then reload the revised plan. If the original sentence disappeared, its thread must say that the recorded target is unavailable instead of guessing a nearby replacement.

Part 2Boundary

2.1 / Acceptance criteria

Ready when revision truth is visible

  • A sent note stays With agent until a validated response exists.
  • A changed outcome names a block present in the computed revision diff.
  • The basic diff distinguishes added, removed, and rewritten authored blocks.
  • Exact structural paths re-anchor; missing paths remain visibly orphaned.
